LLM Baseball

A qualitative LLM coding showcase • Est. 2026

Now Showing • Series 1

LLM Baseball is a baseball fan site built as a qualitative demonstration of LLM coding capabilities. Each feature begins with a single standard prompt and, when needed, the same set of supporting files. That package is handed independently to every participating model, and whatever comes back is preserved here for you to inspect — the hits, the misses, and the errors.

This is a showcase, not a leaderboard. There are no scores, rankings, or preferred models. The only question on the field: did the model produce a functional page from the supplied inputs?

How It Works
  1. A feature is defined by one prompt.
  2. Supporting material is assembled — instructions, images, tabular data, JSON — or the prompt asks models to locate public data and media themselves.
  3. The same prompt and inputs are provided to every participating model.
  4. Each model's implementation is stored in its own subdirectory, together with a copy of the prompt it received.
  5. The feature's index page documents every run and links each functional implementation for preview.

Model output is preserved as submitted, even when incomplete or non-functional. A non-functional result gets no preview link, but its source remains in the repository.

Ground Rules
  • Consistent inputs — models in the same feature receive the same prompt and designated supporting files.
  • Preserved outputs — implementations remain available whether they succeed or fail.
  • Transparent context — run details, costs, tools, and model specs are documented where available.
  • Direct inspection — functional pages run right in your browser; source lives in the repository.
  • Qualitative results — outcomes are demonstrated, not scored.
